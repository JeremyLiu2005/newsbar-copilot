# 規劃：用 LoRA 微調本機小模型寫五字標（未實作）

狀態：**規劃中，未實作、未實測。** 本文只描述方法與上線條件；所有數字都是待驗證的估計。

## 為什麼要做、為什麼現在不做

- **要解決的問題**：本機 qwen2.5:7b 很少剛好寫出 5 個字（11/06 一小時約三分之一），常要重寫或由 AI 從規則候選挑選；雲端模型較準，但要網路、要金鑰、免費額度不穩（11/06 有 45 則沒回應），而且同一題問兩次答案不同。
- **LoRA 能做的**：不改模型主體，只額外訓練一小組參數（約佔模型 0.1–1%），讓本機模型學會三立的寫法：剛好 5 字、保留主角與事件、不寫成定論。訓練完仍在本機執行、不需要網路、答案固定。
- **現在不做的原因**：要有足夠的「人工確認過的標題→五字標」配對。目前只有 TVBS 一小時 26 則人工答案，太少，訓練只會背答案。

## 步驟

### 1. 收資料（在日常回查中自動累積）

- 每一格人工按「通過」或改字，就留下一筆配對：主標題（OCR 原文與修正後）、語音節錄（若有）、最終五字標、台別、日期、是誰確認。
- 只收人工確認過的；AI 自動通過、未經人看的不收。
- 目標筆數：至少 1,000 筆、橫跨 20 個以上播出日、四台都有；含社會、政治、財經、國際、天氣等類別。
- 依日期切分：最後 2 週的資料只拿來評分，不拿來訓練（避免同一則新聞重播被當成答對）。

### 2. 整理成訓練格式

- 每筆轉成和現在提示詞相同的對話格式：系統規則（剛好 5 字…）＋主標題 → `{"short_title": "…", "evidence": [...], "issues": []}`。
- 訓練前先用程式的檢查器（字數、斷詞、不可新增來源沒有的字）過一次；人工答案若沒過檢查，標出來請業師決定規則或答案哪個要改。

### 3. 訓練

- 底模：qwen2.5:7b-instruct（與現行一致）。
- Mac：`mlx-lm` 的 LoRA（4-bit 量化底模，QLoRA）；有 GPU 主機時用 PEFT／Unsloth。
- 起始參數（待調）：rank 16、alpha 32、dropout 0.05；套在注意力層（q/k/v/o）與 MLP；學習率 1e-4、2–3 輪、批次 8。
- 1,000 筆在 Apple M 系列約需 30–60 分鐘（估計，待實測）。

### 4. 評估（和現行版本並排比）

同一批保留資料、同一套檢查器，比較：

| 指標 | 意義 |
|---|---|
| 一次就剛好 5 字的比例 | 不用重寫 |
| 通過全部檢查的比例 | 不用 AI 挑候選、不用規則補標 |
| 和人工答案相同的比例、共用兩字詞的比例 | 貼近三立寫法 |
| 盲評：業師看兩版，選哪個好認 | 最終判準 |
| 換題 F1、廣告 F1 | 必須不變（LoRA 只影響寫標） |

上線門檻（提案設定，待業師確認）：通過檢查比例高於現行版本、盲評不輸現行版本、捏造（寫出來源沒有的字）為 0。

### 5. 上線與退版

- 轉成 Ollama 可載入的 adapter（Modelfile 的 `ADAPTER`），或合併後轉 GGUF。
- 執行紀錄（manifest）記下 adapter 版本與訓練資料範圍；每次換版先跑回歸測試，不通過就不換。
- 每月用新確認的資料重訓一次；新版不過門檻就保留舊版。

## 和現行流程的關係

LoRA 版只取代「本機模型寫標」這一步；檢查器、AI 挑候選、看圖重寫、規則備援與複查分級都不變。
